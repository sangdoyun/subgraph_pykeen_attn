1.2 Required Data Signals (Minimal & Practical)

Signal	Required?	Granularity	Notes

Timestamp	✅	seconds	Needed for alignment
App usage	✅	app open / close	No content inspection
Communication	✅	call/message meta	No message content
Calendar	⚠️ optional	event start/end	High-signal triggers
Location state	⚠️ coarse	home / office / other	No GPS traces
Motion	⚠️ coarse	stationary / moving	From sensors
System state	⚠️	Wi-Fi, headphones	Intent indicators


Key design choice:
👉 Use coarse-grained states, not raw sensor streams
This ensures privacy + battery efficiency.

2️⃣ KPIs (Key Performance Indicators)

KPIs must reflect pattern quality, not model accuracy alone.


---

2.1 Core KPIs (Common Across Patterns)

KPI	Meaning	Why it matters

Stability	Pattern repeats over time	Avoids noise
Confidence	Strength of association	Trustworthiness
Coverage	% of relevant events explained	Practical value
Latency	Time to detect pattern	On-device feasibility
Drift sensitivity	Detects change	User behavior evolves



---

2.2 Temporal Pattern KPIs

KPI	Description

Periodicity score	Strength of alignment at 24h / 7d
Phase stability	Variance of detected time window
Miss tolerance	Pattern survives skipped days
False routine rate	% of spurious routines detected


Good temporal pattern

Appears ≥ K times

Phase variance < threshold

Stable across weeks



---

2.3 Sequential Pattern KPIs

KPI	Description

Lift / dependency score	P(B|A) vs P(B)
Average delay	Time from trigger to action
Trigger coverage	% of triggers followed by action
Precision	% of detected sequences that are real


Good sequential pattern

Lift >> 1

Consistent delay

Repeats across sessions



---

2.4 Contextual Pattern KPIs

KPI	Description

Context lift	P(A|C) vs P(A)
Context purity	How specific the context is
Generalization score	Works when some signals missing
Overfitting rate	Pattern survives context simplification


Good contextual pattern

High lift

Stable across days

Robust to missing context signals

3️⃣ Pattern Evaluation Methodology

This is crucial — how do we prove patterns are correct?


---

3.1 Offline Evaluation (Development / Research)

A. Temporal Holdout Validation

Detect pattern on weeks 1–3

Verify recurrence in week 4


Metric

Reappearance rate

Time-window overlap



---

B. Sequential Counterfactual Test

For each detected (A → B):

Measure P(B | A)

Compare with:

random windows

shuffled triggers



Metric

Lift significance

False discovery rate



---

C. Contextual Contrast Test

Compare behavior inside context vs outside

Ensure context actually changes likelihood



---

3.2 On-Device Evaluation (Production)

A. Silent Prediction Accuracy

When pattern predicts action

Check if action occurs within expected window


Metric

Hit rate

Time error



---

B. Intervention Success (Optional)

If pattern drives a feature:

Measure uplift vs control

Notification acceptance

Task completion



---

3.3 User-Centric Sanity Checks (Optional)

Patterns automatically retire if unused


This prevents stale insights.
