2️⃣ Sequential Pattern Detection

Definition reminder:

> Action B occurs significantly more often after Action A than otherwise, within a meaningful time window.
This requires causality, not just order.



We’ll use this example throughout:

> CLIENT_MEETING_END → REPLY_MANAGER




---

Step 0: Raw Event Stream (Input)

Each event:

<timestamp, event_type, entity_id, attributes>

Example stream:

10:00  CALENDAR_EVENT_END   CLIENT_MEETING
10:06  APP_OPEN             EMAIL
10:07  MESSAGE_SENT         MANAGER
12:30  APP_OPEN             BROWSER

This is noisy and unstructured — no sequence yet.


---

Step 1: Session Construction

Purpose

Ensure sequences are evaluated within meaningful interaction windows, not across unrelated time spans.

Method

Start a new session if:

time gap > X minutes (e.g., 30)

OR location/mode changes



Output

Session S1:
[ CLIENT_MEETING_END, APP_OPEN_EMAIL, MESSAGE_SENT_MANAGER ]

This bounds causality.


---

Step 2: Action Filtering (Candidate Selection)

Purpose

Reduce noise and computation. Only intent-bearing actions should participate in sequences.

Method

Keep:

meeting end

salary credit

missed call

headphone connect

messages, calls, purchases


Drop:

screen on/off

background app switches



Output

Filtered Session S1:
[ CLIENT_MEETING_END, MESSAGE_SENT_MANAGER ]

This makes the next steps precise and cheap.


---

Step 3: Pairwise Dependency List Construction

Purpose

Explicitly enumerate possible causal pairs.

Method

For each session:

For every ordered pair (A → B):

where B occurs within Δt of A (e.g., 30 min)

record (A, B, delay)



Example

(CLIENT_MEETING_END → MESSAGE_SENT_MANAGER, delay = 7 min)

Store as:

Dependency[A][B] += 1


---

Step 4: Measure Sequential Dependence (Core Step)

Purpose

Distinguish true sequences from coincidence.

Computation

For each pair (A → B):

P(B | A) = count(A → B) / count(A)
P(B)     = count(B) / total_events
Lift     = P(B | A) / P(B)

Example

count(CLIENT_MEETING_END) = 10
count(MESSAGE_MANAGER) = 15
count(CLIENT_MEETING_END → MESSAGE_MANAGER) = 8

P(B | A) = 0.8
P(B) = 0.15
Lift ≈ 5.3  → strong dependence

This proves A increases likelihood of B.


---

Step 5: Sequence Interpretation

Purpose

Convert numeric dependence into human-meaningful behavior.

Interpretation Rule

High lift

Short consistent delay

Repeats across sessions


Output

SequentialPattern {
  trigger: CLIENT_MEETING_END
  action: MESSAGE_MANAGER
  avg_delay: 6–8 min
  confidence: high
}


---

Step 6: Consistency Check

Purpose

Eliminate one-off coincidences.

Method

Pattern must:

appear in ≥ K occurrences of A

persist across multiple days/weeks



Example

Observed in 8 of last 10 meetings
→ stable sequence

3️⃣ Contextual Pattern Detection

Definition reminder:

> Action A is significantly more likely in context C than overall.



We’ll use:

> HOME + EVENING → NETFLIX




---

Step 0: Raw Event Stream (Input)

Same base events:

18:42  APP_OPEN  NETFLIX

Plus context signals:

time

location

motion

connectivity



---

Step 1: Context Construction

Purpose

Convert raw signals into a compact, comparable context state.

Method

For each event, derive:

Context C = {
  time_bucket,
  location_state,
  motion_state
}

Example

C1 = { EVENING, HOME, STATIONARY }

This abstraction is critical — no hard-coded semantics.


---

Step 2: Action Filtering

Purpose

Avoid rare or irrelevant actions.

Method

Keep actions occurring ≥ N times in window (e.g., 30 days)

Example candidates:

NETFLIX

FOOD_APP

MUSIC_APP




---

Step 3: Measure Context Dependence

Purpose

Determine if context actually matters.

Computation

For each (C, A):

P(A | C) = count(C ∧ A) / count(C)
P(A)     = count(A) / total_events
ContextLift = P(A | C) / P(A)

Example

P(NETFLIX | HOME+EVENING) = 0.75
P(NETFLIX) = 0.20
Lift = 3.75 → strong context dependence


---

Step 4: Context Generalization

Purpose

Avoid overfitting to overly specific contexts.

Method

If (C, A) is sparse:

drop weakest context dimension

recompute lift


Example

HOME + EVENING + STATIONARY → sparse
HOME + EVENING → stable


---

Step 5: Consistency Check

Purpose

Ensure pattern stability.

Method

Context-action association must:

persist across multiple days

not be driven by a single week




---

Step 6: Final Contextual Pattern Output

ContextualPattern {
  context: HOME + EVENING
  action: NETFLIX
  reliability: high
}
