Below is a clean way to redesign your single Memory Service so it handles both capture (write) and retrieval (read) while keeping the same three memories (working, episodic, semantic). This is the structure reviewers usually expect: clear modules + clear data flow.


---

1️⃣ Single Memory Service – Internal Modules

Inside the Memory Service, group modules into three functional layers:

1️⃣ Memory Processing Layer (shared)
2️⃣ Memory Storage Layer
3️⃣ Memory Retrieval Layer

Some modules are shared between write and read, which is good system design.


---

2️⃣ Memory Service Modules

A. Input Processing / Memory Processing (Shared)

These modules are used when capturing data and also when understanding queries.

1. Query / Input Understanding

Purpose
Interpret incoming information (conversation, device signals, queries).

Input

conversation text
voice
image
device signals

Output

entities
intent
time references

Used for:

memory capture

retrieval queries



---

2. Entity & Relation Extraction

Purpose
Extract structured entities and relationships.

Example

Input

Meeting Rahul tomorrow at 3pm

Output

(User — meeting_with — Rahul)
(time = tomorrow 3pm)


---

3. Fact Builder

Purpose
Convert extracted information into structured facts/triples.

Output format

subject
relation
object
timestamp
confidence
source

Example

User → calls → Rahul
time = yesterday


---

4. Memory Type Scorer

Purpose
Determine which memory type should store the fact.

Output decision

working memory
episodic memory
semantic memory

Example

Meeting event → episodic
User preference → semantic
temporary reasoning → working


---

3️⃣ Memory Organization Modules

These maintain the memory structure.

5. Subgraph / Cluster Formation

Purpose
Group related memory nodes.

Example cluster

work cluster
  office
  meetings
  colleagues

Benefits

faster retrieval

contextual reasoning



---

6. User Preference / Behavior Model (User Manifold)

Purpose
Learn latent user preferences from repeated events.

Example

sushi
ramen
tokyo restaurant

Cluster → Japanese food preference.

Used later in retrieval ranking.


---

7. Memory Controller (Pruning & Forget)

Purpose
Control memory growth.

Functions

memory pruning
decay old memories
compress episodes

Important for smartphone storage limits.


---

4️⃣ Memory Storage Layer

Persistent storage components.

Working Memory

Temporary task state.

Episodic Memory

Events and experiences.

Example

User met Rahul yesterday

Semantic Memory

Stable facts.

Example

Rahul is a contact

Person Knowledge Graph

Stores relationships between entities.

Example

User → works_at → Samsung

Metadata Store (RDB)

Stores indexes

timestamps
confidence scores
memory IDs


---

5️⃣ Retrieval Modules

Used when the agent needs information.


---

8. Retrieval Planner

Purpose
Decide which retrieval strategy to use.

Example

fact query → semantic memory
history query → episodic memory
preference query → manifold


---

9. Hybrid Retrieval Engine

Uses multiple retrieval strategies.

Keyword Search

Used for exact matches.

Example

Rahul
meeting

Vector Similarity

Used for semantic queries.

Example

suggest dinner

Graph Neighborhood Retrieval

Expands around entities.

Example

Rahul → meetings → locations


---

10. Temporal Reasoning

Purpose
Resolve conflicting memories.

Uses

valid_from
valid_to
last_updated

Example

User lived in Seoul (2019)
User lives in Bangalore (2024)

Query:

Where do I live now?

System selects current fact.


---

11. Active Memory Builder

Purpose
Combine retrieved results into final context.

Output

top-k memories

This becomes Active Memory.


---

6️⃣ Data Flow for Memory Capture (Write Pipeline)

Step-by-step flow.

Input (conversation/device signal)
        ↓
Query/Input Understanding
        ↓
Entity & Relation Extraction
        ↓
Fact Builder
        ↓
Memory Type Scorer
        ↓
Subgraph / Cluster Formation
        ↓
User Preference Model
        ↓
Memory Controller
        ↓
Store in:
   working / episodic / semantic memory
   person knowledge graph
   metadata store


---

7️⃣ Data Flow for Memory Retrieval (Read Pipeline)

User Query
        ↓
Query Understanding
        ↓
Entity Detection
        ↓
Retrieval Planner
        ↓
Hybrid Retrieval Engine
   ├ keyword search
   ├ vector similarity
   └ graph traversal
        ↓
Temporal Reasoning
        ↓
Active Memory Builder
        ↓
Active Memory
        ↓
Agent reasoning


---

8️⃣ Modules Shared Between Capture and Retrieval

Shared modules improve efficiency.

Shared components

Query/Input Understanding
Entity Extraction
Knowledge Graph
Metadata Store
User Preference Model


---

9️⃣ Final Architecture Logic

Your memory service performs two core tasks:

Write Pipeline

capture → structure → store

Read Pipeline

query → retrieve → filter → activate

You can describe Memory Service as:

> The Memory Service manages the full memory lifecycle including context capture, memory organization, persistent storage, and hybrid retrieval. It converts raw interactions and device signals into structured memories and retrieves relevant context using hybrid search and temporal reasoning.
