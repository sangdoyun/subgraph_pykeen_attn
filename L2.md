2. Sequential Pattern Detection

(What reliably follows what)


---

Slide 1 — What Is a Sequential Pattern?

Definition

A sequential pattern exists when:

> Action B occurs significantly more often after Action A than otherwise, within a meaningful time window.



NOT a sequence

App launch → app close

Random app switches


Valid sequences

client_meet → reply_manager

salary_credit → shopping

headphones_connected → audio / meeting

missed_call → callback



---

Slide 2 — Raw Data (Starting Point)

Input Events

<timestamp, event_type, entity_id, attributes>

Examples:

10:00  CALENDAR_EVENT_END   CLIENT_MEETING
10:07  APP_OPEN             EMAIL
10:08  MESSAGE_SENT         MANAGER

09:00  BANK_EVENT           SALARY_CREDIT
11:30  APP_OPEN             SHOPPING_APP


---

Slide 3 — Step 1: Session & Window Segmentation

Why this matters

Sequential meaning breaks across long gaps

Method

Create micro-windows after trigger events

Typical window: 5–30 minutes (configurable)


Example

Trigger: CLIENT_MEETING_END
Window: next 30 minutes

Only actions inside this window are considered.


---

Slide 4 — Step 2: Trigger Event Identification

What qualifies as a trigger?

Triggers are state changes or meaningful events, not app launches.

Examples:

Calendar meeting end

Salary credit

Headphones connected

Missed call


These are:

sparse

high-signal

intent-bearing


This keeps computation cheap and accurate.


---

Slide 5 — Step 3: Post-Trigger Action Tracking

For each trigger T, track actions A within the window.

We maintain counts:

Count(T → A)
Count(A)         // global
Count(T)

Example:

CLIENT_MEETING_END → MESSAGE_MANAGER  (8)
CLIENT_MEETING_END → BROWSE           (2)

MESSAGE_MANAGER (global)              (12)


---

Slide 6 — Step 4: Sequential Lift (Key Non-Trivial Step)

Core Question

> “Does A happen because T happened?”



Computation (lightweight)

Lift(T → A) = P(A | T) / P(A)

Interpretation:

Lift ≈ 1 → coincidence

Lift >> 1 → true sequential dependency


This avoids:

frequent but unrelated actions

false positives



---

Slide 7 — Step 5: Confidence & Consistency Check

To confirm the pattern:

Must appear across multiple occurrences of T

Must survive across days / weeks


Example:

CLIENT_MEETING_END → MESSAGE_MANAGER
Appears in 4 out of 5 meetings
→ high confidence


---

Slide 8 — Final Sequential Pattern Output

SequentialPattern {
  trigger: CLIENT_MEETING_END,
  action: MESSAGE_MANAGER,
  avg_delay: 6 minutes,
  confidence: high
}


---

Slide 9 — More Sequential Examples (Very Convincing)

Salary → Shopping

Trigger: Salary credit

Window: 48 hours

Pattern: Shopping activity spike


Headphones → Audio / Meet

Trigger: Headphones connected

Pattern: Audio app OR meeting app

Shows intent activation


Missed Call → Callback

Trigger: Missed call from frequent contact

Pattern: Outgoing call within 15 min

Verified only if:

same contact

repeated across weeks




---

Why Sequential Detection Is Not Trivial

✔ Requires causality, not order
✔ Uses relative likelihood, not frequency
✔ Windowed to avoid noise
✔ Trigger-driven (efficient)
✔ Domain-agnostic

3. Contextual Pattern Detection

(What happens in a situation)


---

Slide 1 — What Is a Contextual Pattern?

Definition

A contextual pattern exists when:

> An action is significantly more likely in a specific context than overall.



Example

At home + evening → Netflix

In office + weekday → Email

Driving → Audio, not video



---

Slide 2 — Raw Data & Context Signals

Raw events

<timestamp, action>

Context signals (derived)

Time bucket (morning / evening)

Location state (home / office)

Motion (stationary / driving)

Connectivity (Wi-Fi / cellular)



---

Slide 3 — Step 1: Context Snapshot Construction

For each action, build a compact context vector:

Context C = {
  time_bucket,
  location_state,
  motion_state
}

Example:

{EVENING, HOME, STATIONARY}

No semantics like “weekend” hard-coded.


---

Slide 4 — Step 2: Context → Action Counting

Maintain lightweight counters:

Count(C, A)
Count(A)
Count(C)

Example:

EVENING+HOME:
  NETFLIX → 12
  FOOD_APP → 7

NETFLIX (global) → 15


---

Slide 5 — Step 3: Context Dependence Score (Key Step)

Core comparison

P(A | C) vs P(A)

If:

NETFLIX happens 80% of the time at HOME+EVENING

but only 20% globally


→ strong contextual dependence

This is not a rule — it’s learned.


---

Slide 6 — Step 4: Context Generalization (Important)

If context is too rare:

drop one dimension

retry


Example:

HOME+EVENING+STATIONARY → too sparse
HOME+EVENING → stable

This avoids overfitting.


---

Slide 7 — Final Contextual Pattern Output

ContextualPattern {
  context: HOME + EVENING,
  action: NETFLIX,
  reliability: high
}


---

Slide 8 — Contextual Examples (Very Practical)

Headphones Connected

Context: headphones + stationary

Action: music

Use: auto-resume playback


Office Context

Context: office + weekday

Action: email, calendar

Use: notification prioritization


Driving Context

Context: driving

Action: audio-only apps

Use: UI simplification, safety



---

Why Contextual Detection Is Not Trivial

✔ Uses relative likelihood
✔ Multi-signal context
✔ Learns soft boundaries
✔ No hand-coded rules
✔ Robust to missing signals


---

Trigger-based computation

Incremental counters

No heavy ML

Bounded memory

Battery-friendly
