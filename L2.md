L2 Patterns: Definition & Identification

1. What L2 Patterns ARE (Very Clear)

L2 patterns are meaningful groupings of L1 patterns that reveal
how a user behaves within a domain.

They answer:

> “Given the user’s raw financial signals, what financial behavior style do they exhibit?”



Examples (finance domain):

Cost-conscious behavior

Credit-dependent behavior

Investment-oriented behavior

Impulsive spending behavior


These are behavior archetypes, not personas.


---

2. What L2 Patterns Are NOT

❌ Not raw signals (that’s L1)

❌ Not single features

❌ Not personas (“budget conscious” is L3)

❌ Not rules like “if coupon > 5”



---

3. Inputs to L2 (Strict)

L2 consumes only L1 outputs.

Example L1 profile for a user (finance):

Salary: Mid

Txn_Frequency: High

Spend_Level: Medium

Credit_Usage: Low

Wallet_Usage: High

SIP: Present

Alerts: High


This vector is the sole input.


---

4. Core Idea Behind L2 Detection

> L2 patterns emerge from recurring co-occurrence of L1 bands.



So the question becomes:

> Which L1 patterns tend to appear together across users (or across time for a user)?



This is where grouping / clustering is appropriate.


---

5. L2 Identification Method (Exact Blocks)

✅ L2 = Feature Encoding → Co-occurrence Modeling → Clustering


---

Block 1: L1 Pattern Encoding

Convert each L1 band into a machine-readable representation.

Options (both valid):

One-hot encoding

Ordinal encoding (Low / Mid / High → 0 / 1 / 2)


Result:

User → L1 Feature Vector


---

Block 2: Domain-Scoped Vector Construction

Construct vectors per domain (finance, sports, etc.).

For Finance:

[ Salary_Band,
  Txn_Frequency_Band,
  Spend_Band,
  Credit_Usage_Band,
  Wallet_Usage_Band,
  SIP_Presence,
  Alert_Intensity_Band ]

This ensures:

No cross-domain pollution

Clear semantic meaning



---

Block 3: Normalization / Weighting (Optional but Recommended)

Normalize feature ranges

Optionally down-weight “background” features (e.g., salary)

Still no rules — just scaling



---

Block 4: Unsupervised Grouping (This Creates L2)

Apply unsupervised grouping to the L1 vectors.

Recommended algorithms:

K-Means (interpretable, scalable)

Hierarchical clustering (better explainability)

DBSCAN (if noise/outliers matter)


This step produces L2 clusters.

Each cluster = one L2 financial behavior archetype.


---

Block 5: Post-hoc Interpretation (Critical)

After clusters are formed, inspect dominant L1 bands per cluster.

Example:

L2 Cluster	Dominant L1 Patterns	Interpreted Meaning

L2-F1	Low Spend, High Coupon, Wallet-Heavy	Cost-sensitive behavior
L2-F2	High Salary, SIP Present, Low Credit	Planned / investment behavior
L2-F3	High Txn, High Spend Var, Credit High	Impulsive behavior


These interpretations:

Are labels, not logic

Can evolve without retraining



---

6. Why Clustering Makes Sense at L2 (But Not L1)

Level	Why / Why Not

L1	Needs stability, semantics → banding
L2	Needs discovery of co-occurrence → clustering
L3	Needs long-term stability → aggregation


This separation is key to explainability.
