The 3 Best Pattern Types (Final Selection)

After filtering for novelty + usefulness + feasibility, these three stand out:


---

1️⃣ Triggerable Latent Routines (TLR)

What it captures

Behaviors that are:

not frequent globally

but highly reliable when a specific context occurs


Example

When user reaches home after 9 PM → orders food

When driving alone → plays music

When airport Wi-Fi connects → opens airline app


This is context-triggered reliability, not frequency.


---

2️⃣ Contextual Substitution Patterns (CSP)

What it captures

Situations where:

context is stable

but multiple actions substitute each other


Example

At home in the evening:

Sometimes Netflix

Sometimes YouTube

Sometimes Music


The context is the habit, not the app.


---

3️⃣ Routine Emergence & Decay (RED)

What it captures

How routines:

form

strengthen

weaken

disappear


Example

Food ordering increasing month over month

Late-night scrolling declining after job change


This captures behavior change without noise.

A context is a lightweight combination of stable signals:

Context C = {
  LocationState,
  TimeBucket,
  MotionState,
  ConnectivityState

Example:

C1 = {HOME, EVENING, WIFI_ON}

Contexts are:

STEP 3: Context → Action Memory (Core Data Structure)

For each context C, maintain:

ActionHistogram[C] = {
  action_i → count_i
}
TotalOccurrences[C]

Example (learned over days):

C = {HOME, EVENING}

FOOD_APP     → 12
NETFLIX      → 7
YOUTUBE      → 5
MUSIC        → 3
Total        → 27

This is cheap, incremental, on-device.


---

STEP 4: Convert to Probabilities

For each context:

P(action | context) = count / total

This single object powers all three pattern types.

Pattern Detection (Same Data, Different Views)

Now the important part.


---

1️⃣ Detect Triggerable Latent Routines (TLR)

Detection Rule (Generic)

A TLR exists if:

P(action | context) is high
AND
Global frequency of action is low

Example

P(FOOD_APP | HOME+EVENING+LATE) = 0.75
Global P(FOOD_APP) = 0.10

➡️ Triggerable Latent Routine detected

Why this is novel

Not “most frequent action”

But most reliable under context



---

2️⃣ Detect Contextual Substitution Patterns (CSP)

Detection Rule (Generic)

A CSP exists if:

Multiple actions have similar probabilities

No single action dominates

Entropy is high within the same context


Entropy(ActionHistogram[C]) > threshold

Example

HOME + EVENING:
Netflix  0.30
YouTube  0.25
Music    0.20
Food     0.15

➡️ Contextual Substitution Pattern

Use

Recommend category, not app

Avoid over-personalization



---

3️⃣ Detect Routine Emergence & Decay (RED)

Key Fix (Your Earlier Concern Addressed)

We do not compare across all time.

Instead:

Track P(action | context) as a time series

Use trend, not difference


For each (context, action):

p_t = EMA(P(action | context) at time t)

Then compute:

slope

confidence interval


Example

HOME+EVENING → FOOD_APP
Week 1: 0.25
Week 2: 0.35
Week 3: 0.50
Week 4: 0.65

➡️ Routine Emerging

If slope < 0 → Routine Decaying
