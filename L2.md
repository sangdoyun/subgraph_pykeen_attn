Common Ground (Applies to All Patterns)

Before any pattern detection, the phone does three very basic things:

Step 0.1 – Event Stream

The phone observes a stream like:

(time, type, value)

Examples:

(08:30, APP_OPEN, NEWS)

(18:45, LOCATION, HOME)

(18:50, APP_OPEN, FOOD_APP)

(19:10, APP_OPEN, NETFLIX)


This is the only raw input.


---

Step 0.2 – Time Windows

All patterns work over fixed rolling windows, for example:

last 7 days

last 30 days


This avoids reacting to one-off behavior.


---

Step 0.3 – Sessionization

Events are grouped into sessions using simple rules:

new session if gap > X minutes

new session if location/mode changes


Result:

Session S = [e1, e2, e3 …]

Now we start pattern-specific logic.

1️⃣ TEMPORAL PATTERNS

(When something repeatedly happens)

Goal

Detect regular time-based routines (daily, weekly).


---

Step-by-Step Method

Step 1.1 – Time Binning

For each action (e.g., NETFLIX), create a time grid:

Example (30-min bins):

Mon 18:00–18:30 → 1
Mon 18:30–19:00 → 1
Tue 18:00–18:30 → 0
…

This gives a binary timeline.


---

Step 1.2 – Compare the Timeline With Itself (Shifted)

We now ask:

> “Does this pattern look similar if I shift it by 24 hours? 7 days?”



So we:

shift the timeline by 24h

count how often both original and shifted have 1 in the same bin


If this overlap is consistently high, a daily routine exists.

No FFT, no heavy math — just overlap counting.


---

Step 1.3 – Stability Check

We repeat the above for:

week 1

week 2

week 3


If the overlap stays high → real routine
If it fluctuates → noise


---

Output

TemporalPattern:
- action: NETFLIX
- period: weekly
- time_window: Fri 19:00–22:00
- confidence: high


---

Why This Is Clear & Accurate

Doesn’t rely on averages

Requires repetition across weeks

Handles weekday/weekend naturally

2️⃣ SEQUENTIAL PATTERNS

(What happens after what)

Goal

Detect repeated action orders, not just co-occurrence.


---

Step-by-Step Method

Step 2.1 – Extract Action Sequences

From each session, extract only action order:

Example:

[LOCATION_HOME → WIFI_ON → FOOD_APP]

Store these sequences.


---

Step 2.2 – Count Short Sequences First

Start with length-2 sequences:

A → B

Example:

HOME → FOOD_APP  (12 times)
HOME → NETFLIX   (4 times)


---

Step 2.3 – Check If Order Matters

We compare:

How often B happens after A

vs how often B happens overall


If:

P(B | A) >> P(B)

then A → B is meaningful.


---

Step 2.4 – Extend Only When Useful

Try extending:

A → B → C

Keep it only if it improves prediction over B → C.

This prevents long, meaningless chains.


---

Output

SequentialPattern:
- sequence: HOME → FOOD_APP
- confidence: high
- avg_delay: 10 minutes


---

Why This Is Clear & Accurate

Learns order only when order matters

Avoids combinatorial explosion

Very efficient on-device

3️⃣ CONTEXTUAL PATTERNS

(What happens in a situation)

Goal

Detect actions that depend on context, not just frequency.


---

Step-by-Step Method

Step 3.1 – Build Context Snapshots

For each session, create a small context vector:

Context = {time_bucket, location, motion}

Example:

{EVENING, HOME, STATIONARY}


---

Step 3.2 – Record Context → Action Pairs

We keep counters like:

Context C:
  FOOD_APP → 8
  NETFLIX  → 5
  MUSIC    → 2

Also keep global action counts.


---

Step 3.3 – Compare Context vs Global

For each action A:

how often A happens in context C

how often A happens overall


If A is much more likely in C, then it is context-dependent.

This comparison is the key — not raw counts.


---

Output

ContextualPattern:
- context: EVENING + HOME
- action: FOOD_APP
- reliability: high


---

Why This Is Clear & Accurate

Separates “likes” from “situational habits”

No hand-written rules

Sparse, incremental updates

4️⃣ SOCIAL INTERACTION PATTERNS

(With whom, and when)

Goal

Detect stable social rhythms, not just frequent contacts.


---

Step-by-Step Method

Step 4.1 – Build Interaction Timeline per Contact

For each contact:

Contact A:
  Tue 20:00 → call
  Fri 21:00 → call


---

Step 4.2 – Track Interaction Strength Over Time

Each interaction increases a score. Old interactions slowly fade.

This avoids “one busy week” bias.


---

Step 4.3 – Detect Repeated Time Slots

We check:

> “Does this contact appear repeatedly in similar time slots?”



Example:

Calls every Sunday evening → strong pattern

Random times → weak pattern



---

Output

SocialPattern:
- contact: FAMILY_MEMBER
- rhythm: weekly (Sunday evening)
- strength: strong


---

Why This Is Clear & Accurate

Captures relationship strength

No message content needed

Very lightweight graph (few nodes)



---

5️⃣ CONSUMPTION PATTERNS

(How content is consumed)

Goal

Detect styles of consumption, not just what app is used.


---

Step-by-Step Method

Step 5.1 – Represent Each Session Simply

Each session becomes a vector like:

(duration, interaction_rate, time_of_day)

Example:

5 min, high interaction → “quick check”

60 min, low interaction → “lean-back viewing”



---

Step 5.2 – Group Similar Sessions

Sessions that look similar are grouped together over time.

This grouping is incremental:

new session joins closest group

new group created only if needed



---

Step 5.3 – Track Group Stability

If a group:

keeps reappearing

across many days


→ it is a consumption pattern


---

Output

ConsumptionPattern:
- mode: LONG_FORM_EVENING_VIEWING
- typical_time: night
- stability: high


---

Why This Is Clear & Accurate

Distinguishes usage style

Works across apps

Very low dimensional
