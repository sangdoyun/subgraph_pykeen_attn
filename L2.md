2️⃣ SEQUENTIAL PATTERN DETECTION

(What tends to happen after what)

Goal (Precise)

Detect repeated action orders, such as:

“After reaching home, user opens food app”

“After starting driving, user opens music app”

“After opening email, user opens calendar”


A sequential pattern means:

> Action B occurs significantly more often after Action A than otherwise.




---

Step 0: Raw Data

Same raw events:

(timestamp, event_type, event_id)

Example:

18:42 LOCATION_HOME
18:44 WIFI_ON
18:50 APP_OPEN FOOD_APP


---

Step 1: Session Construction (Critical)

Sequential patterns only make sense within a session.

Step 1.1 – Define Session Boundaries

Start a new session when:

time gap > X minutes (e.g., 30)

location changes

activity/mode changes


Output

Session S = [e1, e2, e3]


---

Step 2: Extract Action Sequences

From each session:

keep only action events (apps, calls, media)

preserve order


Example:

[HOME → FOOD_APP]
[DRIVING → MUSIC_APP]


---

Step 3: Learn Pairwise Dependencies First

Step 3.1 – Count Transitions

For every ordered pair (A → B):

count how many times B follows A within a short window (e.g., 15 min)


Also track:

how often B occurs overall



---

Step 3.2 – Check If Order Matters

Compute:

Lift = P(B | A) / P(B)

If Lift > threshold:

A → B is a real sequential dependency


This filters out coincidence.


---

Step 4: Extend Sequences Only When Useful

Try longer sequences:

A → B → C

Keep them only if:

they improve prediction beyond B → C


This avoids long, meaningless chains.


---

Final Output

SequentialPattern {
  sequence: HOME → FOOD_APP,
  avg_delay: 8 min,
  confidence: high
}


---

Why This Is Accurate

Requires predictive improvement

Learns order only when it matters

Works with sparse data

3️⃣ CONTEXTUAL PATTERN DETECTION

(What happens in a situation)

Goal

Detect behaviors that depend on context, e.g.:

“At home in evening → Netflix”

“At airport → cab app”


A contextual pattern means:

> An action is much more likely in a specific context than globally.




---

Step 0: Raw Data

Events + context signals:

time

location

motion

connectivity



---

Step 1: Build Context Snapshots

For each session or event, construct:

Context C = {time_bucket, location_state, motion_state}

Example:

C = {EVENING, HOME, STATIONARY}


---

Step 2: Count Context → Action Occurrences

Maintain:

Count(C, A)
Count(A)  // global
Count(C)

Incremental counters only.


---

Step 3: Measure Context Dependence

For each (C, A) pair, compare:

P(A | C) vs P(A)

If:

A happens much more often in C → context matters


This removes “always-used apps”.


---

Step 4: Context Generalization (Avoid Sparsity)

If context is too rare:

drop one dimension (e.g., motion)

recompute


This keeps patterns robust.


---

Final Output

ContextualPattern {
  context: EVENING + HOME,
  action: NETFLIX,
  reliability: high
}


---

Why This Is Accurate

Compares in-context vs global

No hard-coded rules

Handles missing signals

5️⃣ CONSUMPTION PATTERNS

(How content is consumed)

Goal

Detect styles of consumption, e.g.:

quick checks

long focused sessions

background listening


A consumption pattern means:

> Sessions with similar structure repeat over time.




---

Step 0: Raw Data

Session-level info:

app category

duration

interaction count



---

Step 1: Represent Each Session Simply

Each session → vector:

V = {duration, interaction_rate, time_bucket}

Low dimensional (3–5 values).


---

Step 2: Group Similar Sessions

When a new session arrives:

compare to existing groups

join closest group

create new group only if very different


This is incremental and cheap.


---

Step 3: Track Group Stability

If a group:

appears often

across many days


→ it is a consumption mode


---

Final Output

ConsumptionPattern {
  mode: LONG_FORM_EVENING_VIEWING,
  typical_duration: 60–90 min,
  stability: high
}

Why This Is Accurate

Captures how, not just what

Works across apps

Resistant to noise
