2. Common Foundational Modules (Shared)

These modules are mandatory and are where a lot of the “non-trivial” value lives.


---

Module 1: Signal Normalization & Event Encoding

Purpose

Convert heterogeneous phone signals into a unified event representation.

Input

App usage

Location changes

Connectivity states

Communication events

Media sessions


Output (canonical event)

<timestamp, event_type, entity_id, attributes>

Example:

<18:42, APP_LAUNCH, NETFLIX, {duration=45m}>
<08:10, CALL, CONTACT_A, {outgoing}>

Why this matters:

Enables generic downstream processing

Removes app-specific logic



---

Module 2: Sessionization & Temporal Segmentation

Purpose

Group events into meaningful behavioral units.

How

Time-gap–based segmentation

State-boundary detection (e.g., location change)

Activity-mode transitions


Output

Session S = {e1, e2, …, en}

Example:

Commute session

Evening home session

Social interaction session


Why non-trivial:

Prevents mixing unrelated behaviors

Crucial for accuracy downstream



---

Module 3: Context Construction

Purpose

Construct a compact, structured context vector per session or event.

Context dimensions (examples)

Time bucket

Day type

Location state

Motion / device state

Network state


Output

Context C = <c1, c2, … ck>

Important:

Context is structured, not raw

No hard-coded semantic rules



---

Module 4: Unified Behavior Store

Purpose

Provide a shared data substrate for all pattern detectors.

What it stores

Event sequences

Session summaries

Context–action pairs

Temporal indexes


Think of this as:

> a behavioral knowledge substrate, not a log.

3. Pattern-Specific Detection Modules

Now the pipeline branches. Each module reads from the same store but applies a different analytical lens.


---

Module 5A: Temporal Pattern Detection Module

Goal

Detect stable periodic routines (daily, weekly, seasonal).

Method sequence

1. Aggregate event occurrences into time series


2. Analyze periodicity at multiple resolutions


3. Score phase stability across windows



Key techniques

Autocorrelation + spectral analysis

Stability over rolling windows

Noise suppression via consistency scoring


Output

<event/action, period, phase, confidence>


---

Module 5B: Sequential Pattern Detection Module

Goal

Detect ordered action dependencies.

Method sequence

1. Extract ordered event sequences from sessions


2. Learn variable-length dependencies


3. Retain only sequences that improve predictability



Key techniques

Variable-order Markov modeling

Predictive gain scoring

Sequence pruning


Output

<A → B → C, confidence, avg_gap>


---

Module 5C: Contextual Pattern Detection Module

Goal

Detect behaviors that are strongly context-dependent.

Method sequence

1. Build context → action mappings


2. Estimate action distributions per context


3. Measure context sensitivity vs global behavior



Key techniques

Mutual information (context, action)

Context generalization to avoid sparsity

Confidence-weighted distributions


Output

<Context C, Action A, reliability_score>


---

Module 5D: Social Interaction Pattern Module

Goal

Detect stable social interaction structures and routines.

Method sequence

1. Build temporal interaction graph


2. Track edge strength dynamics


3. Identify recurring interaction motifs



Key techniques

Time-decayed graph weighting

Reciprocity & responsiveness metrics

Temporal community detection


Output

<Contact cluster, interaction rhythm, strength>


---

Module 5E: Consumption Pattern Module

Goal

Detect latent modes of content/service consumption.

Method sequence

1. Represent sessions as consumption vectors


2. Discover latent modes


3. Track mode activation and transitions



Key techniques

Session embeddings

Mixture / mode discovery

Mode persistence scoring


Output

<Consumption mode, activation contexts, stability>
