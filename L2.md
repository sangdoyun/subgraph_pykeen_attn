1️⃣ Memory Service — Module Descriptions

Purpose:
Convert raw smartphone signals + conversations into structured memory objects.


---

Entity / Relation Extraction

What it does

Extract structured entities and relationships from conversations and device data.

Examples:

Input:

"Meeting Rahul at 3pm tomorrow"

Output:

Entity: Rahul (contact)
Event: Meeting
Time: tomorrow 3pm
Relation: user → meeting_with → Rahul

How

Possible techniques:

NER models

LLM extraction prompts

rule-based patterns for device data


Example pipeline:

text → entity detection → relation extraction → triple generation


---

Fact Builder

What it does

Convert extracted entities into structured facts stored in the knowledge graph.

Example:

(User → meets → Rahul)
(time = tomorrow 3pm)

Also attaches metadata:

confidence
timestamp
source

How

Simple KG triple creation:

subject – relation – object


---

Memory Type Scorer

What it does

Decides where memory should be stored:

working memory
episodic memory
semantic memory

Example:

Conversation event
→ episodic memory

Stable fact
→ semantic memory

Current task context
→ working memory

How

Scoring based on features:

recency
repetition
semantic stability
temporal relevance

Example rule:

if repeated fact → semantic
if single event → episodic


---

Mem Controller (Pruning & Forget)

What it does

Controls memory size on device.

Responsibilities:

remove outdated memory
compress episodes
decay rarely used memories

Example:

restaurant visited once 2 years ago → remove

How

Possible strategies:

recency decay

frequency scoring

summarization


Inspired by:

MemoryBank forgetting curve


---

Subgraph / Cluster Formation

What it does

Groups related memories into semantic clusters.

Example cluster:

work cluster
  ├ office
  ├ colleagues
  ├ meetings

Why useful:

faster retrieval

contextual reasoning


How

Possible methods:

graph community detection
embedding clustering


---

User Manifold

What it does

Represents latent user behavior patterns.

Examples:

food preferences
social habits
travel patterns

Example:

Observed data:

sushi restaurant
ramen restaurant
tokyo cafe

Manifold cluster:

Japanese cuisine preference

How

Embedding + clustering methods:

PCA
UMAP
spectral clustering

Result becomes habit nodes in KG.

3️⃣ Retriever Engine — Module Descriptions

Purpose:

---

Query Understanding Module

What it does

Analyzes user query to determine:

intent
entities
time constraints
query type

Example:

Query:

"When did I last meet Rahul?"

Output:

intent: history
entity: Rahul
memory type: episodic

How

Possible techniques:

LLM classification

rule-based intent detection



---

Retrieval Planner

What it does

Decides which retrieval methods to use.

Example:

fact query → semantic memory
history query → episodic memory
preference query → manifold + semantic

Instead of fixed retrieval.


---

Hybrid Retrieval Engine

Uses multiple retrieval strategies.


---

Keyword Search

Good for:

exact entities
names
events

Example:

Rahul
meeting

Technique:

BM25


---

Vector Similarity

Retrieves semantically similar memories.

Example:

Query:

suggest dinner

Finds:

previous restaurant visits

Technique:

embedding similarity


---

Graph Neighborhood Retrieval

Expands around entities.

Example:

Rahul

Retrieve:

Rahul → meetings
Rahul → calls
Rahul → contacts

Technique:

1-hop or 2-hop graph traversal


---

Temporal Reasoning

Filters memory based on time.

Important for conflicting facts.

Example:

User lived in Seoul (2019)
User lives in Bangalore (2024)

Query:

Where do I live now?

Temporal filter selects:

valid_to = current

Metadata used:

valid_from
valid_to
last_updated
